Where the Director Attaches

A design party · 2026-09-17

One director, one local marvel, and a question that sounds small: which NATS server does the director dial? Five researchers went to the source and came back agreeing.

The verdict. The director attaches to the broker on its own host and to nothing else. When a durable global tier exists, that local broker is a leaf of the shared infrastructure NATS, and the leaf carries global and cross-cluster reach. The director's code is the same in every deployment; only the local broker's leaf config changes. The peer the director must never lose is its own supervisor, one hop away, so no wide-area link sits in the path that must not break.

The adopted shape: local-only, leaf bridge

The director's socket lands on the local broker. Everything global rides the animated leaf link, which the director never has to hold or manage.

Nyx

NATS internals

A client attaches to one server at a time. Two connections mean two deliveries per publish on any shared subject, continuously, not just under fault. Soundest: the leaf bridge. Inadvisable: tandem.

Winston

Architecture

Attach where the peer you must not lose is closest. That is the local supervisor. The leaf gives global reach at zero extra connection cost. One default for every shape.

Per

Platform ops

A local patch bounces one connection into reconnecting, buffers in order, resubscribes on return. Set reconnect to unlimited so the client waits out the update. Global-only would route local work through the tier's uptime.

Dr. Quinn

Failure analysis

Rule tandem out: subject overlap across two live connections is a duplicate-delivery pattern in NATS's own issue history. One connection moves split-brain from client logic to a single, controllable broker fact.

Mara

Availability

A home-internet blip is the most likely outage. A local connection has no wide-area hop in its failure path, so the blip cannot touch the director-to-local-cluster link. The adaptivity lives in the leaf config, a deploy-time fact, not in the director's code.

The one real argument

Winston wanted to keep tandem in reserve for a real need: reaching remote clusters when the local leaf is down. Dr. Quinn wanted it ruled out. Nyx settled it from the internals: the duplicate is structural and steady-state, not a fault-window tax, so tandem's cost is paid every day, not only on a bad one.

Rejected, with reasons kept: global-only (nothing to dial in the common case, wrong link in the other), migrate (a move is a disconnect and a lossy cutover), tandem (a standing duplicate that needs dedup and a presence-owner rule to behave).

Recommendation held for the operator. Full rationale, failure block diagram, sequence and transaction views in recommendation.md.
Every load-bearing fact was web-verified against the NATS documentation before anyone took a position.
