The Retrospector Keeps No Secret Drawer

A design party · 2026-09-17

A role that studies how the team works had been told to stash its notes outside the repo, behind a small fortress of write locks. The room sent it back to what the old hand already did: write in the open, propose, and let someone else land the change.

The verdict. The retrospector owns no path outside a project's own repository and keeps no private state drawer. It writes only its own append-only record, named the way the reviewer names its store, "the record the team reads," and never a fixed path. It proposes; a consuming seat or a human applies the change. Most of the write-restriction machinery falls away.

Propose, hand off, land: the shape worth keeping

The retrospector's arrow stops at the record. It never reaches the code or the library; that is somebody else's, through a governed change.

Three tiers, one write, three consumers

Tier 1

code and PR vs the spec

Goes to the surface already there: a note on the PR or the story. Read by the seat on that PR.

Tier 2

spec vs PRD and architecture

An append-only record. The spec or architecture seat lands a governed change.

Tier 3

root cause at charter and doctrine

The same record, tagged, routed to a human. No cross-project drawer the retrospector owns.

Sage

Prior-art harvest

The old hand kept its record in the repo and let another agent land the change. Drop the outside-git drawer. If a cross-project home is ever forced, the standard shape exists; an invented path is not it.

Ravi

Hand-off design

Emit, do not hoard state. Resume from the tail of your own record, each line noting what it was written against. One model across tiers; only the consumer changes.

Sable

Sandbox and security

A misdirected write inside git is revertible; a trust-bypassed write to the library is not. Keep the trust-strip for that asymmetry; drop the schema field the harness never reads.

Isolde

Component independence

A fleet-wide drawer, by any name, is the dependency the operator already rejected. Tier 3 emits and hands off. Bare mode is not a fallback; it is the only mode the code must support.

Recommendation held for the operator; wardrobe#11 stays held and the role stays not-live. The write-surface schema field (P3) is retired before landing.
